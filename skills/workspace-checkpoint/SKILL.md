# Workspace Checkpoint

把本次工作整理成可续作的项目记忆和可审查的本地提交。**项目活文档是事实源，自动记忆只保存摘要与链接。**

## 不可违反的边界

- 只提交能从当前会话和 diff 确认归属的改动；不明文件原样保留并列出。
- 不自动 merge、不自动 push、不改写历史，不默认添加 `Co-Authored-By`。
- 不自动 stash，不直接使用 `git clean -fdx`，不删除无法明确再生的文件。
- 不记录密码、token、密钥或个人敏感信息。公开文档前必须另行获得明确要求并脱敏，不写项目背景、内部路径、业务数据或个人信息。
- 没有实际变化时不创建空提交；没有证据时不声称完成或测试通过。

## 执行流程

### 1. 收集事实

1. 阅读项目 `AGENTS.md`、`CLAUDE.md` 或其他项目指令与文档约定，遵循当前任务的会话上下文。
2. 在本 skill 目录运行：

   ```bash
   python scripts/audit_workspace.py --root <项目根目录> --json
   ```

   脚本只读。非 Git 项目则只检查文件，不伪造 Git 状态或提交。
3. 检查 `git status`、暂存与未暂存 diff、近期提交。区分本任务改动和他人的/不明改动。
4. 当前在特性分支则沿用；不自动合并。若在禁止直接提交的 main：仅文档整理可创建 `docs/memory-*`，有代码改动则先询问分支名。

### 2. 读取并起草项目活记忆

1. 优先沿用项目声明的记忆路径；只有项目未声明时，才采用检查 JSON 的 `suggested_memory_path`。否则有 `docs/` 时用 `docs/ai-memory.md` 并登记现有文档索引；没有文档体系时用根目录 `AI_MEMORY.md`。
2. 以 `assets/ai-memory-template.md` 为初始结构；已有文件则在原文上更新，不覆盖用户有效内容。
3. 写入绝对日期，保留**最近 30 天**的工作摘要；更早内容从“最近工作”移除，但相关事实仍可由提交和主题文档追溯。
4. 每条工作摘要尽量包含：做了什么、为什么、关键文件/提交、验证证据、仍未解决的问题。不要把整段 git log 或会话流水复制进去。
5. “踩坑与有效做法”按问题去重更新，记录根因和以后怎么做；无依据的内容标“待确认”。稳定规则提炼到 `AGENTS.md` 或主题文档后，活文档只留链接。
6. 若宿主 AI 支持持久记忆，则同步该记忆：更新已有项目摘要和索引，只写当前状态摘要及项目活文档链接，不复制整篇记录。删除已被证实错误的旧记忆；不支持的宿主只保留项目活文档。

### 3. 验证

- **有代码或行为变更**：先跑相关测试，再跑项目完整测试。判定口径改动必须有回归用例。失败则不提交代码，保留失败输出并写入记忆。
- **纯文档**：检查变更文档的相对链接和 `git diff --check`，不强行运行无关业务测试。
- **UE 插件或编辑器行为**：遵循项目要求留下编译、自检或有头验证证据，不能用 Python 测试替代。
- 验证命令与结果写入记忆；跳过或未执行的项目明确说明。

### 4. 保守清理

1. 在验证之后清理本轮生成的 `__pycache__`、`.pytest_cache`、`.pyc` 和已确认临时文件。
2. 删除 PID 文件前确认进程已退出；删除截图、报告或诊断文件前确认它们不是正式产物。
3. 正式输出、用户数据、共享缓存、编辑器/宿主配置和不明未跟踪文件全部保留。清理后再次检查 Git 状态。

### 5. 回写、提交与报告

1. 将最终验证、清理、保留和失败信息回写项目记忆，再同步自动记忆摘要；不得保留验证前的陈旧状态。
2. 代码和测试按任务目的提交；项目记忆与索引用独立 `docs:` 提交。遵循仓库现有中文提交格式。
3. 提交前运行 `git diff --cached --name-only` 和 `git diff --cached --check`，确认暂存区只有已审查的本任务内容，再用普通 `git commit` 提交。若暂存区混有其他任务内容，先精确调整暂存区；不要用 `git commit --only <path...>` 代替审查，因为它会把指定路径未暂存的修改也纳入提交。
4. 只本地 commit，不 push。已有提交或没有新内容时，不为迎合流程创建空提交。
5. 最终列出：记忆文件、验证命令和真实结果、提交哈希、清理项、保留项、失败/跳过事项。若有未完成代码，不得把任务整体称为完成。

## 停止并询问的情况

- 需要 push、公开敏感信息、重写历史或合并分支。
- 需要删除不确定的文件，或不明改动与本任务冲突。
- 测试失败且无法在不扩大任务范围的情况下修复：停止代码修复和代码提交，但仍可回写失败证据并独立提交记忆；若记忆提交归属也不明确，再暂停询问。
- 当前在 main 且有代码改动，分支归属不明确。
