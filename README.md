# AI 编程准则

与 AI 结对编程时强制执行的质量规范，目标是把质量内化到代码生成阶段，而不是事后返工审查。

## 7 维自查协议概览

1. **正确性与健壮性** — 边界条件、具体错误处理、资源泄漏、输入验证
2. **🚫 零容忍重复（DRY）** — 3 次法则强制、结构重复检测、禁止防御性复制、跨文件扫描、测试代码亦需 DRY
3. **可读性与可维护性** — 精准命名、单一职责（函数 ≤50 行、嵌套 ≤3 层）、注释写 Why
4. **性能与效率** — 复杂度、I/O 批量化、内存克制、避免 N+1 查询
5. **安全性** — 禁止硬编码敏感数据、输入清洗、入口权限校验、依赖无高危漏洞
6. **可测试性** — 核心逻辑解耦、契约明确、关键路径有单测建议
7. **工程规范** — 架构分层、日志规范、完整类型注解

其中 **DRY 与正确性为硬阻塞项**，不达标必须在输出最终代码前自行修正。

每次输出代码后附带《自查报告》：

```
✅ 自查通过项:  [通过的维度编号及名称]
🔍 DRY 扫描结果: [未发现重复 / 已消除的重复点 / 合理豁免理由]
⚠️ 已修正项:    [发现并已修复的问题]
❓ 待确认项:    [需人类决策的设计权衡或潜在风险]
💡 优化建议:    [非阻塞改进方向]
```

## 使用方式

- 直接将文档内容作为系统提示 / 规则（如 KSCC.md、AGENTS.md、Cursor Rules）注入给 AI 助手；
- 或者在代码评审时当作人工 checklist 使用。
